## What Was Built

### §2.1 — Attendance Confirmation Gate
- **Migration**: `web/db/migrations/009_attendance_confirmations.sql` — new table with unique index on `(event_id, user_id)`
- **DB helpers added** to `web/db.js`:
  - `createAttendanceConfirmation`, `updateAttendanceConfirmation`, `getAttendanceConfirmation`, `getPendingAttendanceConfirmations`
- **`runAttendanceGate()`** in `web/cadence.js`:
  - Queries users for events >12h past with no confirmation row
  - Batches all pending events into ONE SMS per user
  - Single-event: "Did you make it to X on Day? (Y / N / skip)"
  - Multi-event: numbered format with "Reply 1Y 2N or skip"
  - Creates `pending_action` with type `attendance_confirm` + `createAttendanceConfirmation` rows
  - Guard: never sends second confirmation for same event
  - Wired into `startNudgeLoop` after `runNudgeScan`
- **`attendance_confirm` handler** in `web/server.js`:
  - Parses Y/N/skip, 1Y 2N, bulk yes/no patterns
  - Updates `attendance_confirmation` records (attended=1/0/null, confirmed_at)
  - Calls `lift.computeAndLogLift()` after Y or N (not skip)
  - Does NOT re-prompt

### §2.2 — Proposal Provenance
- **Migration**: `web/db/migrations/010_proposal_provenance.sql` — `proposals` table
- **DB helpers**: `createProposal`, `updateProposalOutcome`, `getProposalByEvent`
- **`web/cadence.js`** `nudgeUser()`: after successful SMS, creates proposal row with `origin='cadence_nudge'`
- **`web/agent.js`**:
  - Module-level `recordProposal(userId, origin, opts)` and `convertProposal(proposalId, eventId)` helpers
  - `suggest_venues` handler: calls `recordProposal(userId, 'agent_discovery', ...)`
  - `create_social_event` handler: looks for prior cadence proposal to convert; if none, records `user_request` and links to event

### §2.3 — FLAI Ledger + Burn Meter
- **Migration**: `web/db/migrations/011_flai_ledger.sql` — append-only ledger (user_id nullable for system/unknown)
- **`web/flai.js`** (new file):
  - `BURN_RATES` (provisional, commented)
  - `BASELINE_GRANT = 100`, `EARN_RATE_CAP = 500` (stub)
  - `burnForUser(userId, reason, opts)` — appends negative delta, never throws, logs would-throttle
  - `checkThrottle(userId)` — STUB, always returns `{throttled: false, level: 'full'}`
  - `capEarnRate(userId, proposed)` — STUB, returns proposed unchanged
- **DB helpers**: `appendFlaiLedger`, `getFlaiBalance` (via SUM, no stored column)
- **`db.createUser()`**: grants BASELINE_GRANT after INSERT, ledger failure non-fatal
- **Burn instrumentation** (STUB, always permissive):
  - `web/agent.js`: `flai.burnForUser(userId, 'burn:llm', {ref_id: response.id})` after each Anthropic call
  - `web/sms.js`: `flai.burnForUser(null, 'burn:sms', {ref_id: msg.sid})` in both `send()` and `sendUnchecked()`
  - `web/venues.js`: `flai.burnForUser(null, 'burn:places', {})` after Places API call

### §2.4 — Lift Instrumentation

### Bugs found and fixed by tests
1. **Auth bypass (security):** `/app/*` pages were served by static middleware BEFORE auth ran — unauthenticated users could access protected pages. Fixed: added `/app` auth guard middleware before `express.static()`.
2. **Phone validation:** OTP send accepted garbage input. Fixed: E.164 regex check after `toE164()`.
3. **Migration gap:** `db.js` only applied `web/db/migrations/` — missing 8 tables including `consent_records`. Fixed: now applies both `db/migrations/` AND `web/db/migrations/` sorted together.
4. **Chat history ordering:** `ORDER BY created_at ASC LIMIT 50` returned oldest 50 messages. Fixed: `DESC LIMIT + reverse` returns most recent 50 in chronological order.
