# 2026-06-18 — ButterflAI SMS Debug Marathon

Long session getting inbound SMS working end-to-end. All resolved by ~22:21 UTC.

## Root causes (in order found):

1. **Messaging Service had no inbound webhook** — phone number is in A2P Messaging
   Service MG21e... (for campaign registration) but service had `inbound_request_url: null`.
   Fix: set `InboundRequestUrl: https://butterflai.social/inbound` on the service.

2. **`sendUnchecked` trapped inside lazy-init** — defined inside `_initDefaultClient()`
   which only runs when `_getClient()` is first called. Always `undefined` on first use → 
   TypeError silently swallowed. Fix: move to top-level export.

3. **`sendUnchecked` used undefined `client`** — should be `_defaultClient`.

4. **`sendUnchecked` called undefined `toE164`** — not imported in sms.js. Removed.

5. **Twilio blacklisted `/sms` after 500** — after broken validation caused a 500,
   Twilio permanently stopped calling `/sms` (no recovery, no alerts for future msgs).
   Fix: fresh `/inbound` path. Both `/sms` and `/inbound` now on same Express handler.

6. **Signature validation scope bug** — `twilio.validateRequest` used where `twilio`
   was out of scope. Fix: `require('twilio').validateRequest(...)` inline.

7. **Proxy URL reconstruction** — Fly.io TLS terminates at edge; `req.protocol` is
   always `http`. Must use `x-forwarded-proto` / `x-forwarded-host` headers.

## Key Twilio learnings:
- After a 500 webhook response, Twilio blacklists that URL path permanently (no recovery)
- Messaging Service URL takes precedence over phone number `sms_url`
- TwiML outbound-reply is suppressed on A2P 10DLC long codes — use REST API instead
- A2P campaign registration creates a Messaging Service but doesn't configure its webhook
